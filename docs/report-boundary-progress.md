# 报告边界 v1

当前问题是正文把已知的分析程序操作重新写成不确定的远端行为。已有计数及来源校验正确，
四条正文却仍出现来源混淆或把中点插入写成字符替换，JSON 格式验收不能发现这类问题。

新增的独立离线报告层明确分工：程序生成有限字段事实和限制，模型正文默认待审阅，
逐条语义审阅与文件绑定通过后才能作为模型推测与限制纳入。它不修改 v3 核心源文件，
因而原协议的全部模块指纹和已保存实机结果仍可重算。研究上要分别报告工具调查、
字段覆盖、来源重提取、结构检查、语义审阅、正文纳入，不能合成一个成功率。

验收使用两条路线：已上传实机结果离线重算，以及控制夹具测试。夹具中的批准记录和
来源凭据仅用于验证门槛，不能算作真人评测或真实模型实验。实机审阅是助手辅助审阅，
不是独立人工标注；其四条拒绝原样保留。报告层的效果是隔离待审阅或被拒绝的正文，
不是提升模型语义正确率。缺失计数、布尔计数、截断、重复 occurrence、错引用、
不匹配审阅绑定、来源校验覆盖不足，都有明确失败路径。

已完成的阶段：v3 小批调查及离线重算、已保存字段来源校验、报告边界实现与实机回放。
仍待完成的研究证据：独立人工审阅、更多独立案例及真实流量、跨模型小批对照。
不能把工程完成程度换算成模型语义准确率，暂不以一个百分数概括整个项目。

下一轮有预算时再冻结新的实验协议，在固定分母下比较程序报告与经过独立审阅的模型
解释，记录正文拒绝原因与字段覆盖。先复用现有案例，不默认扩大调用批次，也不混入
本次报告层的实现变更来重新解释旧 v3 条件比较。
