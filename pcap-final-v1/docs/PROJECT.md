# 工程说明与讲解材料

## 项目解决的问题

把本机PCAP分析变成有输入边界、可保存证据、可复核结果的工具流程。
起点是让AI调用抓包工具；最终实现将模型的工具选择与程序生成事实分开。
模型可能选错工具或写出非法参数，因此控制器负责路径、预算、schema、调用记录和发布边界。

一个简洁的项目介绍可以这样说：

> 我实现了一个本地只读PCAP分析MCP服务，提供12个工具。模型根据目标和概览选择工具，控制器验证参数并绑定输入文件。HTTP字段的存在性、展示值和来源转换由程序记录，再从原包重提取复核。实验中也出现过模型添加非法参数的情况，这些请求会被拒绝并保留失败。最终报告发布程序观察，不把模型自由正文当作已经核验的事实。

## 一次运行怎样完成

1. 检查文件格式、路径和资源限制，固定输入文件摘要。
2. 自动生成概览，记录为E01。
3. analyze模式按用户指定直接调用工具；agent模式向本机模型发出一次工具选择请求。
4. 控制器验证工具名及闭合参数，补入固定路径；HTTP证据模式也由控制器补入。
5. 保存原始响应、执行或拒绝记录、完整受限工具输出。
6. 发布可用程序观察；HTTP导出字段再做原包复核并生成字段事实表。
7. 输出REPORT.md、程序JSON、来源证明与摘要清单，打成同名ZIP。

输入快照保存在结果目录的input中，原输入文件不修改；同名ZIP也包含这个快照。

agent模式是一次工具选择，最多两个后续工具。模型不读取这些后续结果再继续规划。
概览和工具结果受各自采样及大小限制，不能把保存结果称为完整网络行为真值。

## 12个工具

| 工具 | 主要用途 |
| --- | --- |
| summarize_capture | 文件信息、包量、主要协议、通信端点概览 |
| list_conversations | TCP/UDP/IP通信对及流量排名 |
| inspect_dns_queries | 查询名称、频次与返回码 |
| inspect_http_requests | HTTP请求字段；完成版使用字段证据模式 |
| show_protocol_hierarchy | 协议层次及占用 |
| find_tcp_anomalies | 重传、乱序、零窗口等解析器迹象 |
| analyze_handshake_failures | 握手观测及未完成迹象 |
| measure_rtt | 有限样本内解析器提供的RTT统计 |
| detect_suspicious_patterns | 需要进一步核实的启发式迹象 |
| check_tls_posture | 服务端握手版本及SNI；不是客户端能力即协商结果 |
| find_cleartext_credentials | 可能的明文凭据位置，不返回凭据值 |
| run_display_filter | 受限显示过滤及允许的元数据字段 |

tshark/capinfos承担协议解析，MCP承担工具通信。MCP本身不是真值引擎，也不替代解析器。

## HTTP字段怎样复核

同一个字段必须区分：存在且有值、存在但为空、没有导出到该字段。
“present=true、display_value为空”不能写成字段缺失。
展示中的中点、控制字符清理、URI后缀移除及脱敏等转换，必须保留程序来源及计数。
原包复核逐条比较已导出字段记录；覆盖范围是这些字段出现位置，不是整个抓包，也不证明对端意图。

完成版对非空HTTP字段记录要求复核后才发布对应输出；没有HTTP记录时仅说明解析器本次未观察到请求，不能把空记录表当作逐字段核验成功。
DNS/TLS/TCP的日常结果是解析器程序输出，不自动获得HTTP字段级来源证明。

## 为什么没有继续让模型写最终事实

历史模型曾把空值说成缺失，同模型自动审阅又认可了错误。
已知正反例校准的反例检出不足，自动语义审阅保持关闭。
因此当前交付边界是：模型选工具，程序发布受限观察；不会自动修改模型错误来追求全通过。

## 参数和预算

每个工具只接受其schema声明的参数。字段选择参数不能借给不接收它的HTTP工具。
参数“合法”和“符合目标”是不同问题。例如top_n=20可能合法，但不能满足“只要1条”的目标。
日常agent入口没有参考答案，因此不会自动宣称已充分回答任意目标；原始参数和结果供使用者判断。

每项模型调查显式指定RunId，最多一次生成。请求前保存dispatch-intent，超时或HTTP500也占用该次尝试。
同一编号再次运行或report导出不重试；直接analyze不调用模型。
RunId改变输入或目标时会拒绝覆盖旧计划。不同新调查可以使用不同编号，但不以改名重试同一失败来改写实验。

与完成多协议对照的运行副本相同，仅此前analysis.py已有DNS布尔表示兼容修正；本次没有改核心算法。
pc_shared、pc_wire、pc_planner、pc_lock沿用最后一轮实跑的原字节。
run_project.py与两个PowerShell脚本提供统一日常入口及说明安装。

原工程src不覆盖；旧批次保留其原始响应、预算与分数。历史核查见results/project-history-review.txt。
该历史文件截至当时的核查，后续公共样例及最终配对结果以RESULTS.md和本次核验记录为准。

## 交付范围

当前约定的工程交付已经收尾：有可运行入口、可复核资料、已保存的实际模型对照、统一说明及明确限制。
模型总体优势、独立生产数据、自然语言自动语义验收、生产部署以及多轮自主调查没有被本交付证明。
这些限制不应在面试、报告或后续论文中省略。
