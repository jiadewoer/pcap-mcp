# pcap-mcp：可复核的本地抓包分析工程

工程完成版交付日期：2026-10-18。

项目通过本地MCP接口调用Wireshark解析抓包，将工具执行、字段来源、参数拒绝、原始模型响应和报告一起保存。
当前日常入口为 `pcap-final-v1\Run-PCAP.ps1`，请从 [START-HERE.md](START-HERE.md) 按命令运行。

核心有12个只读工具。模型模式由本机Ollama选择后续工具，控制器绑定抓包路径并验证闭合参数schema。
HTTP事实表由程序生成，导出的字段记录再从原包复核；DNS、TLS、TCP等结果以程序观察发布。

支持的日常模式：

| 模式 | 用途 | 新模型请求 |
| --- | --- | --- |
| check | 运行源码、解析器、实际MCP注册表检查 | 0 |
| analyze | 直接生成概览及指定协议的程序结果 | 0 |
| agent | 单次选择0至2个工具并保存结果 | 最多1 |
| report | 导出已有结果或失败记录 | 0 |
| serve | 作为MCP stdio服务等待客户端调用 | 本服务自身为0 |

RunId绑定一次调查。模型请求前保存占位；同一RunId不会自动重试或续跑。
报告保留工具错误、参数拒绝、截断和来源验证失败，模型自然语言正文不发布。

最后一轮开发对照已核验：A组8/8、B组8/8，冻结关键词规则为4/8。
A/B在本批打平，没有观察到额外参数提醒的增益。
上一轮多协议实验的模型7/8及参数错误仍保留，未重跑或改分。

这些是已暴露公共开发样例上的描述性结果，不证明总体模型优势、生产泛化或抵抗提示注入。
自动语义审阅仍关闭；同版本字段重提取证明有限字段一致性，不能证明行为意图或攻击成功。

原src和旧实验目录均保留。完成版通过独立runtime选择已经核验的源码，并兼容DNS布尔字段的0/1及False/True表示。
安装脚本只在检查通过后备份并更新根目录说明，不自动拉取模型或安装依赖。
